## §1 三层次观测模型（本项目实例化）

> 通用模型见 dev-meta 07。本节补充**本项目的实例化判据**。

| 层 | 手段 | 回答的问题 | 自动化 | 环境 |
|----|------|-----------|--------|------|
| **O1 断言** | 单测 / 契约断言 | 「代码是否正确」 | ✅ 全自动 | 本地 + CI（Node 环境，纯逻辑层） |
| **O2 埋点** | 运行时日志（`observe`） | 「运行中发生了什么、走了哪条分支」 | ❌ 人工 | 扩展宿主（Extension Host），输出至 Output Channel |
| **O3 回读** | 真机端到端验证 | 「最终交付给用户的是否正确」 | ❌ 人工 | 仅真机（VS Code 安装 `.vsix`） |

> **编号约定**（唯一权威 `dev-meta 07 §2.6`）：`L1 / L2 / L3` = 契约层级；`O1 / O2 / O3` = 观测层级。本文不复述。

- **判据**：智能体/进程产物离开本进程（此处为**出站 HTTP 请求**）时 **O3 不可省**；平台专属失效模式下 **O2 不可被 O1 替代**（细则见 `dev-meta 07 §2.6`）。
- **平台约束**：本项目的受限环境是 **VS Code 扩展宿主**——① 无稳定 stdin/stdout 可用于用户可见输出，日志必须走 Output Channel；② 宿主进程与 UI 线程共享，热路径打点会直接体现为输入卡顿；③ 不得假设 `node_modules` 之外的运行时依赖；④ 网络可能被企业代理拦截，失败必须可判别。故 **O2 是唯一排障入口**，且必须默认低开销。

## §2 关键路径埋点清单

> 与 `02_SYSTEM_DESIGN.md` §5「须被观测的关键路径」一一对应。

| 阶段 / 函数 | 层 | 须含字段 | 判别量（标量 / 计数 / 布尔） | 是否高开销 | 状态 |
|-------------|----|----------|---------------------------|-----------|------|
| `infra/git.readStagedDiff` | O2 | Elapsed / 工作区根 / 是否 git 仓库 | `hunkCount`（计数）、`isEmpty`（布尔） | 是（子进程） | ⬜ |
| `infra/diffParser.parseDiff` | O1 + O2 | 输入字符数 / 输出块数 | `hunkCount`（计数）、`filesTouched`（计数） | 否 | ⬜ |
| `core/contextBuilder.buildContext` | O2 | 每块 payload 字节数 | `maxPayloadBytes`（标量，须 ≤ 2048）、`truncatedCount`（计数） | 否 | ⬜ |
| `infra/jevClient.decide` | O2 | Elapsed / 请求块数 / 重试次数 | `httpStatus`（标量）、`retryCount`（计数）、`concurrency`（标量） | 是（网络） | ⬜ |
| `core/threshold.filterRisky` | O1 + O2 | 输入块数 / 命中块数 / 阈值取值 | `inputCount` / `hitCount`（计数）、`threshold`（标量） | 否 | ⬜ |
| `ui/status.reportStatus`（降级分支） | O2 | 失败原因码 / 是否静默放行 | `errCode`（标量）、`degraded`（布尔） | 否 | ⬜ |
| `ui/riskList.showRiskList` → 跳转 | O2 + O3 | 目标文件 / 行号 / 是否命中 | `itemCount`（计数）、`navigated`（布尔） | 否 | ⬜ |

- **高开销节点**（I/O、网络、模型推理、跨进程）**必须**含 `Elapsed Time` + 关键资源指标（dev-meta 07 §2.3）。
- **热路径禁无条件打点** + Release 无运行期日志开关旁路（dev-meta 07 §2.7）——本项目的日志开关**只由构建期常量或 `sonecheck.debug` 配置在激活时读取一次**，不在每次检查时重新求值。

## §3 失败面与错误码留痕

> 契约侧定义见 `03_CONTRACTS_AND_API.md`；本节定义其**运行时留痕方式**。

| 错误码 | 触发场景 | 日志级别 | 是否重抛 | 是否断言 |
|--------|----------|----------|----------|----------|
| `ERR-01` | 网络不可达 | warn | 否（降级放行） | 是（出站前后各一次断言：请求已构造 / 已降级） |
| `ERR-02` | 请求超时 | warn | 否（降级放行） | 是（超时上限为命名常量） |
| `ERR-03` | 非 2xx | warn | 否（降级放行） | 是（记录 `httpStatus`） |
| `ERR-04` | 配额耗尽 / 鉴权失败 | error | 否（降级放行） | 是（Key 存在性断言，不含 Key 值） |
| `ERR-05` | 响应 schema 不合规 | error | 否（丢弃该块） | 是（字段存在性与取值范围断言） |
| `ERR-06` | 非 git 仓库 | warn | 否（终止） | 否 |
| `ERR-07` | 暂存区无改动 | info | 否 | 否 |
| `ERR-08` | API Key 未配置 | error | 否（终止） | 是（密钥可读性断言） |
| `ERR-09` | git 可执行文件缺失 | error | 否（终止） | 否 |
| `ERR-10` | 用户取消输入 | info | 否 | 否 |
| `ERR-11` | 输入空串（清除 Key） | warn | 否 | 是（清除前二次确认布尔） |

- **不隐式吞错**：`catch` / 降级分支须「记录并重抛」或「记录并回退兜底态」（dev-meta 07 §2.1）。本项目的兜底态是 **`Degraded` → 放行**（`02` §4），**必须留痕后再放行**，禁止 `catch {}` 静默。
- **出口 Assert**：映射 / 查表为空、状态非法、越界等「不该发生但会发生」的点，须断言而非静默返回（dev-meta 07 §2.5）。本项目重点：payload 字节数超限、hunk 行号越界、响应 `score` 不在 `[0, 1]`。

## §4 本项目 `observe` 包装器

- **落地位置**：`src/infra/logger.ts`（导出 `observe<T>(stage, fn, fields)` 与 `log(event)`）。
- **输出目标**：VS Code **Output Channel**（`sonecheck`），单行 JSON，便于直接贴给 AI 排查。
- **生产隔离方式**：由 `sonecheck.debug` 配置在**激活时读取一次**决定是否输出详细字段；错误与降级路径**始终输出**（不依赖开关）。
- **单次检查单一 `inspectionId`**：同一次检查的所有日志行携带同一 ID（时间戳 + 随机短串），便于串联完整链路 —— 无 `inspectionId` 的日志视为违规。
- **模板选择**：本项目为 TypeScript/Node 环境，包装器形态以 `dev-meta 07 §4` 的 JS/TS 模板为准。
- **历史散落 `console.log` 盘点**：0（项目尚未开始编码）。**首条红线**：此后新增代码禁止裸 `console.log`，一律经 `observe` / `log`。

## §5 DoD 核对（合并前）

- [ ] **无裸露日志**：关键路径全部经 `observe(...)` 包装，不散落原始 `console.log`。
- [ ] **写逻辑即写观测**：关键节点同步注入结构化日志 + 出口 Assert，逻辑与观测不可分离提交。
- [ ] **无静默吞错**：所有 `try-catch` / 降级分支均有诊断快照留痕。
- [ ] **高开销节点覆盖**：I/O / 网络 / 推理 / 跨进程均含 `Elapsed Time` + 资源指标。
- [ ] **Log-Driven 排查**：报错时只贴结构化日志 / Crash / Trace，不向 AI 描述自然语言现象。
- [ ] **验证闭环**：构造坏数据时能输出可解析的诊断上下文，复制给 AI 后可一次定位。
- [ ] **轨迹可判别**：观测点均有判别量，无「只报到达某步」；判读表无模糊行（07 §3.2）。
- [ ] **轨迹验证在完整逻辑层**：经集成 / E2E 断言「一次命中」，未以单测代替（07 §3.2）。
- [ ] **无旁路 + 计数同处**：Release 无运行期日志开关（靠构建期门控）、热路径无非 once 打点；失败计数与抛错点同处（07 §2.7 / §2.1）。

> DoD 唯一权威为 dev-meta 07 §7；本清单为项目侧核对副本，如有差异以 07 为准。
